Abstract

A constant input matrix, and a criterion

Koopman operator models enable sampling-based Model Predictive Path Integral (MPPI) control to roll out thousands of sampled input sequences through a low-cost learned lifted model. However, recent Koopman MPPI controllers keep a constant input matrix, which is suitable for convex Koopman MPC, but not needed for sampling. It fixes a single gain from input to tracked output, yet for many robots the true gain varies with heading or attitude.

This paper supplies a criterion for when the states a task visits rule out such a matrix. If the output is read linearly from the lifted state, the largest gap between the predicted and true gains over those states is at least half the true gain's variation. This holds for any lifting features and every horizon step, but the criterion says nothing if the input moves the output only by acceleration or higher derivatives.

Where the gain varies strongly, as for a freely turning unicycle or a drone over a wide yaw range, linear rollouts fail. A bilinear rollout, where the input matrix instead depends on the lifted state, stays close to the true-model oracle. Its MPPI update costs under twice the time of a linear update. Where the gain varies little, the linear rollout is less accurate than the bilinear one in most tests but can remain within the task tolerance. Yet passing the criterion is not enough. In a pendulum swing-up, linear models of matching width fail at long horizons even for outputs with a constant one-step input gain, while bilinear models with the same outputs can succeed. The cheaper linear rollout is therefore worth trying at small gain variation, but a closed-loop test is still needed to confirm it works for a given task.

Contributions

What the paper adds

  1. A necessary condition for a constant input matrix. With a linear readout, a linear lifted model has one input gain everywhere. Over the states a task visits, its worst-case gain error is then at least half the gain variation νΦ, at every horizon step and for any dictionary.
  2. Where the criterion rules linear out. On the unicycle and on a drone with a wide yaw range, linear rollouts fail, while the bilinear one stays near the oracle and needs less than twice the linear MPPI update time. A graded drone study shows that the point of failure depends on the tolerance.
  3. Where it does not, and its limit. At small variation, the cheaper linear model can meet the tolerance, though the bilinear one is usually more accurate. On a torque-driven arm, the linear error stays small for the joint angles but grows with the one-step gain variation for the end effector. Passing the test is still not enough. In a pendulum swing-up with a horizon of 30 steps or more, bilinear models can succeed, whereas linear models of the same width fail in every tested setting, even when they predict the angle itself, whose one-step gain is constant.
The criterion

When is a constant input matrix ruled out?

Under a linear readout, a linear lifted model predicts the same input gain at every state. Somewhere on the states a task visits, it therefore misses the true gain Φ by at least half its variation νΦ, whatever the lifting features. The normalized variation ν̂ lies between 0 and 2.

ν̂ small

A narrow heading range

When the visited headings stay in a narrow range, the input gain stays nearly constant and the bound is small. The criterion does not rule the linear rollout out, and whether it is accurate enough becomes a closed-loop question. If the input reaches the tracked output only through acceleration or higher derivatives, the first-order gain is zero and the criterion says nothing.

ν̂ large

A freely turning heading

When the heading turns freely, the rotation sweeps the gain across its range, and a velocity-commanded vehicle reaches ν̂ = 2. A linear lift is ruled out once the bound exceeds the task tolerance. A larger lift does not help, since the input still multiplies the same constant matrix. A bilinear rollout, whose input matrix depends on the lifted state, can follow the change.

Method

Two ways for the input to enter

Koopman methods lift the state through a dictionary into z = Ψ(x), and MPPI rolls thousands of sampled input sequences through the lifted model. The question is how the input u enters that rollout.

Linear rollout
z+ = A z + B u

One constant input matrix B for every state, the form used by recent Koopman MPPI controllers.

Bilinear rollout
z+ = A z + B0 u + Σi ui (Bi z)

The input also multiplies the lifted state, so the predicted input gain changes with the state.

The cost reads the observables back linearly, b = C z. Writing M(u) = A + Σi ui Bi, the bilinear step becomes z+ = M(u) z + B0 u, which costs m+1 matrix–vector products against one for the linear model. Its predicted input gain is affine in the lifted state, so it can match the true gain on the visited states exactly when that gain is affine in the lifted features. Each model learns its dictionary jointly with its matrices, and both use the same architecture, data, and multi-step loss.

Bilinear Koopman MPPI · one control step
  1. Lift the current state once, z0 = Ψ(x).
  2. Sample K input sequences vt(k) = Pc(ut + εt(k)), with ε ∼ 𝒩(0, Σ) and Pc the identity or a projection onto the input set.
  3. Roll each through the bilinear model z+ = M(v) z + B0 v, accumulating the trajectory cost S(k) on the predicted observables.
  4. Update the plan: ut ← ut + (Σk w(k) εt(k)) ∕ (Σj w(j)),  w(k) = exp(−(S(k) − minj S(j)) ∕ λ).
  5. Apply u0 projected onto the input set, shift the plan, and warm-start the next control step.

Graded gain variation

The drone's yaw range sets ν̂ = 2 sin ψ̄ (2 beyond ψ̄ = π/2). The linear open-loop error grows with it and stays within 2% of a constant-gain least-squares predictor, while the bilinear error stays below 0.006 m. In closed loop, the bilinear controller's mean tracking error is within 0.006 m of the oracle's in every episode. All linear episodes succeed up to ν̂ = 0.40, 0.96, or 1.43 for tolerances of 0.10, 0.15, or 0.25 m. The criterion bounds the one-step input-response error, not the tracking error, so it does not predict these levels.

Other rollout classes

Every class gets the same data, training budget, and MPPI. A larger linear lift does not help. On the drone, the rollouts with a state-dependent input gain come within 7% of the oracle, except a decoder whose training collapsed. On the unicycle, only the bilinear model and the neural model with clamped inputs come close, the latter at one to two orders of magnitude more operations per step.
